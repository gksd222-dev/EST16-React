훅은 언제 실행되고,
렌더는 어디서 일어날까?

함수 컴포넌트의 한 생애는 마운트 → 업데이트(반복) → 언마운트입니다. 매 순간 React는 렌더 단계에서 화면을 계산하고, 커밋 단계에서 DOM에 반영한 뒤, 브라우저가 그림을 그리면 이펙트를 실행합니다.

04

꼭 짚고 넘어갈 포인트

POINT 1

렌더 ≠ DOM 업데이트

렌더는 "함수를 호출해 결과를 계산하는 것"일 뿐입니다. 결과가 같으면 커밋에서 DOM은 바뀌지 않아요. 그래서 렌더 함수 본문은 순수해야 합니다.

POINT 2

useLayoutEffect는 페인트 전, useEffect는 커밋 후

레이아웃 측정·깜빡임 방지처럼 그리기 전에 꼭 끝나야 하는 일만 useLayoutEffect로. 나머지(데이터 요청, 구독, 로그)는 useEffect가 기본입니다.

POINT 3

cleanup은 이전 값을 기억한다

cleanup은 다음 이펙트 실행 직전과 언마운트 때 실행되고, 자신이 만들어질 때의 state를 클로저로 들고 있습니다. 그래서 effect cleanup 0 → effect 1 순으로 찍혀요.

POINT 4

setState는 즉시 바뀌지 않는다

setState는 업데이트를 큐에 넣고 리렌더를 예약할 뿐입니다. 현재 렌더의 count는 스냅샷이라 그대로예요. 같은 이벤트 안의 여러 setState는 묶어서(batching) 한 번에 렌더됩니다.

setCount(count + 1);
console.log(count); // 아직 이전 값
POINT 5

같은 값이면 리렌더를 건너뛴다

Object.is로 비교해 이전 state와 같으면 React는 자식까지의 렌더를 생략(bail-out)합니다. 객체·배열을 직접 수정하면 참조가 같아 화면이 안 바뀌는 이유이기도 해요.

POINT 6

StrictMode에서는 두 번 실행된다

개발 모드에서 React는 컴포넌트 함수를 두 번 호출하고, 마운트 직후 이펙트 → cleanup → 이펙트를 한 번 더 돌려 cleanup 누락을 찾아냅니다. 프로덕션에서는 한 번만 실행돼요.

※ 클릭·키 입력처럼 사용자가 직접 일으킨 업데이트는 React 18 이후 useEffect를 페인트 전에 동기로 실행할 수도 있습니다. 확실히 "그리기 전"이 보장되는 건 useLayoutEffect뿐이라고 기억하면 됩니다. · 실행 순서는 React 18/19 기준입니다.
